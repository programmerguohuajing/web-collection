## 1. 背景与定位

2026-08-26 对参考系统进行了全功能走查（16 个页面，截图与结构化数据存档于临时探查目录），结合 8/19 既有对比计划，确认双方定位差异：

| | 参考系统（埋点平台） | 本系统（Web Collection） |
|---|---|---|
| 核心价值 | 业务数据采集质量与业务分析 | 异常发现 → 根因定位 → 知识沉淀 |
| 强项 | 事件契约、口径治理、业务漏斗、用户链路、远程熔断 | 错误聚合、AI 诊断、rrweb 回放、Trace、知识库 |
| 弱项 | 无 AI、排障深度浅 | 事件口径不统一、无链路视图、无远程止血 |

**本 PRD 集合的目标**：补齐「洞察层」与「治理层」短板，但所有功能围绕本系统北极星设计——*缩短"发现异常到定位根因"的路径*，而非复制埋点分析平台。

## 6. 全局设计原则

1. **排障优先**：新功能必须能从异常场景一键进入；每个洞察页提供「AI 分析」入口（消费现有 diagnoser/知识库）
2. **零埋点优先**：优先复用已采集数据；需 SDK 改动的（04/06）单独排期并保证旧 SDK 降级安全
3. **口径透明**：所有统计页在页头展示口径说明（借鉴参考系统"业务时区/去重口径"注释风格）
4. **双后端一致**：所有新 API 同时实现 Node(PG) 与 Cloudflare(D1)，能力开关对齐
5. **合规内建**：敏感字段默认脱敏，完整数据需等级授权（07）
6. **保留期约束**：原始 events 仅保留 30 天、logs（events type='log'）14 天（governance.retention）；凡涉历史趋势/健康判定的口径以此为准。各分册预聚合日表统一保留 ≥180 天并纳入治理配置（详见各册数据模型节）
