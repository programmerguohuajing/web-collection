# PRD 03：版本质量（Version Quality）

> 优先级：P1 ｜ 里程碑：M2 ｜ SDK 改动：无
> 修订：2026-08-26 评审修订——received_at 已核实双端存在（开放问题 1 关闭）；基线计算增加最小样本门槛；补充保留期说明
> 落点：发布管理页新增「版本质量」Tab
> 关联：消费数据 events / errors / sessions；与告警中心联动

## 1. 背景与问题

- 发版后"新版本有没有引入问题"需要人工在错误页切换版本筛选对比，无直接结论；
- 参考系统数据显示单应用可并存 25+ 个 SDK 版本——版本不收敛时，问题定位与用户升级策略都无从下手；
- 参考系统「版本质量」页提供了正确范式：按版本聚合 Contract 接受率、异常会话率、上报延迟，并标注版本运行表现。

## 2. 目标 / 非目标

**目标**
- G1 每个版本一行的质量总览：采用规模、错误密度、异常会话率、上报延迟
- G2 任意两版本并排对比（错误 TopN、性能分位），直接回答"新版比旧版好吗"
- G3 新版本 48h 观察期自动监控，错误率超基线告警
- G4 版本收敛建议（低采用率+老版本提示推动升级）

**非目标**
- 不做版本发布流程管理（发布动作仍在研发侧）
- 不做 App 强更/推送（只做观测与建议）

## 3. 用户故事

- 作为发布负责人，发完 1.2.0 后打开版本质量页，观察期内看到"错误/千会话 8.2 vs 基线 6.1，🟡 偏高"，点开对比视图发现新增错误 Top1 是 `ChunkLoadError`，立即决策回滚。
- 作为 SDK 维护者，看到 0.1.0-alpha.42 以下版本合计采用率 3%，发起收敛通知。

## 4. 功能需求

### FR-1 版本质量列表

| 列 | 口径（页头展示） |
|---|---|
| 版本 | release_name（App 版本）与 sdk_version 两组维度可切换 |
| 采用用户 | 区间去重 user_id |
| 会话数 | session_id 去重 |
| 错误/千会话 | errors × 1000 / 会话数 |
| 异常会话率 | 含 ≥1 次错误的会话 / 总会话 |
| 上报延迟 P75 | received_at − ts（received_at 列双端已存在：PG db.js / D1 migrations/0011_events_envelope.sql；上线前抽查两端写入填充率，未填充样本不计入分位） |
| JS 错误数 | errors 计数 |
| 性能分 | LCP/INP P75（有数据时） |
| 状态 | 🟢健康推荐 / 🟡观察 / 🔴建议回滚 / ⚪建议收敛 |

- 筛选：应用、平台、时间范围（默认近 7 天）
- 排序默认按采用用户降序

### FR-2 状态判定规则

| 状态 | 规则 |
|---|---|
| 🔴 建议回滚 | 观察期内（发布后 48h）错误/千会话 > 全站基线（排除自身）× 2 |
| 🟡 观察 | 发布后 48h 内；或错误密度高于基线 1.2~2 倍 |
| ⚪ 建议收敛 | 采用率 < 5% 且最后出现时间 > 14 天前 |
| 🟢 健康 | 其余 |

- 基线 = 该应用全部其他版本加权平均，页头展示基线值
- 基线稳健性门槛：仅将会话数 ≥10 的版本计入加权平均（与单版本展示门槛一致），避免长尾小样本稀释基线；sdk_version 维度下 alpha 小版本众多，基线仍按应用整体计算并在口径注明

### FR-3 版本对比视图

- 选择 A/B 两版本并排：
  - 错误 Top10 对比表（错误指纹、A 次数、B 次数、差异标记「新增/消失/持平」）
  - 性能指标对比（LCP/INP/FCP P75）
  - 采用趋势曲线（近 14 天）

### FR-4 观察期告警联动

- 新版本进入观察期时，若命中 🔴 规则 → 推送告警中心（复用现有 alert 渠道），消息含版本号、指标值、对比链接

### FR-5 收敛建议

- ⚪ 版本行展开：受影响用户数、最近会话时间、一键复制"升级通知"文案

## 6. 数据模型

无新表；全部基于 events/errors 聚合。需预聚合日表 `release_daily_stats(release, day, users, sessions, errors)` 避免长区间扫描（与 02 共用预聚合基建）。该表保留 ≥180 天——原始 events 仅保留 30 天，14 天采用趋势与跨期对比依赖此表。

## 7. 边界与异常

| 场景 | 行为 |
|---|---|
| 版本数 > 50 | 表格分页；对比选择器支持搜索 |
| 新版本数据不足（<10 会话） | 状态显示"数据不足"，不参与基线计算 |
| release_name 缺失（老 SDK） | 归入"未版本化"分组，置底展示 |

## 8. 成功指标

- 新版本故障 MTTD（发布到发现）< 30 分钟
- 版本收敛：低采用率老版本数量环比下降
- 版本对比功能周使用 ≥ 5 次
- 基线前置：上线前 2 周记录现状 MTTD 与人工切版本对比耗时，作为环比基线
